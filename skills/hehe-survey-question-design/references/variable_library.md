# 用户调研变量库 v0.1

## 用途

本文件用于把研究目标拆成可测变量，再映射到题型、题目、图表和报告结论。

它不是题库，而是问卷设计的变量积木。

## 核心变量组

| 变量组 | 典型变量 | 常见题型 | 后续分析用途 |
|---|---|---|---|
| 样本甄别 | 年龄、性别、城市、生活阶段、婚育/孩子阶段、目标品类经验、品牌经验、角色身份 | 单选、多选、下拉、填空 | 样本筛选、配额、终止规则、Base 定义 |
| 人群分类 | 已有用户、潜在用户、流失用户、家长/学生、B端采购/使用者、劳动者/消费者 | 单选、多选、隐藏题 | 后续分群、跳题、交叉分析 |
| 认知触达 | 第一认知渠道、进一步了解渠道、常用平台、广告触达、信息来源 | 单选、多选、排序 | 获客路径、触媒策略、营销渠道 |
| 使用行为 | 使用频率、使用时长、使用品类、使用品牌、使用场景、最常用功能、核心工具 | 单选、多选、矩阵单选 | 用户成熟度、行为分层、场景渗透 |
| 购买/付费行为 | 是否购买、购买时间、购买渠道、价格水平、支出占比、复购/续费、付费订阅状态 | 单选、多选、矩阵单选 | 转化链路、价格带、商业化空间 |
| 决策因素 | 购买考虑因素、选择平台/品牌因素、功能偏好、课程选择因素 | 多选、限选、排序 | 因素提及率、优先次序、产品定位；需估计权重时另选相应测量设计 |
| 动因 | 初次使用原因、学习动因、购买动因、频率提升原因、持续使用原因 | 多选、单选 | 增长驱动、核心价值感知 |
| 痛点/阻碍 | 使用问题、学习问题、未购买原因、流失原因、迁移原因、功能未满足 | 多选、开放题 | 产品机会、流失归因、改进方向 |
| 场景/任务 | 信息搜索、文本写作、视觉创作、工作办公、学习备考、孩子学习辅导、家政服务场景 | 多选、矩阵多选、场景分支 | 场景渗透、任务价值、场景化报告章节 |
| 满意度评价 | 整体满意度、维度满意度、功能表现评分、品牌满意度变化 | 单选、矩阵单选 | 满意度图表、品牌/产品对比、TOP2/均值 |
| 推荐/继续使用 | NPS、推荐意愿、继续使用意愿、复购意愿、回归可能 | 单选、量表 | 忠诚度、留存、口碑潜力 |
| 品牌竞争 | 品牌认知、曾用品牌、当前主品牌、最常用品牌、品牌迁移、忠诚品牌、替代品牌 | 单选、多选、隐藏题、矩阵单选 | 竞争格局、迁移路径、品牌定位 |
| 功能/Kano | 功能有无评价、功能重要性、功能吸引力、功能缺失影响 | 普通功能评价按目标选量表、限选或排序；Kano 用正反成对题 | 功能优先级、MVP 判断；功能有无的满意反应用 Kano 分类 |
| 价值观/态度 | 教育理念、消费观、职业规划、学习观、健康观、信任边界、生活压力 | 矩阵单选、多选 | 用户分群解释、画像深描 |
| 背景交叉 | 收入、学历、职业、行业、城市、家庭结构、孩子年龄、企业规模 | 单选、下拉、矩阵 | 交叉分析、人群画像、报告分层 |

## 研究目的映射

| 研究目的 | 优先变量组 | 最容易漏掉的变量 |
|---|---|---|
| 新品需求验证 | 样本甄别、场景/任务、痛点/阻碍、功能/Kano、付费意愿 | 当前替代方案、未使用原因、场景强度 |
| 满意度研究 | 使用行为、整体满意度、维度满意度、推荐/继续使用、痛点 | 具体使用阶段、主品牌或主产品、问题归因 |
| 产品体验研究 | 场景/任务、功能表现、痛点、继续使用、开放反馈 | 场景下的真实任务，而不是泛功能评价 |
| 竞品比较 | 品牌认知、曾用/当前主品牌、迁移原因、维度满意度、替代意愿 | 过去-现在-未来的迁移路径 |
| 付费转化研究 | 使用行为、价值感知、价格/支出、付费状态、转向品牌 | 不付费原因、免费替代品、付费后迁移 |
| 用户画像/分群 | 样本甄别、行为链路、价值观/态度、背景交叉 | 只收背景信息、不收行为变量 |
| AI 应用研究 | 使用阶段、任务场景、主工具、品牌迁移、信任/可信度、付费迁移 | 从尝鲜到工作流嵌入的节点 |
| B端/SaaS研究 | 角色身份、使用场景、采购决策、协作链路、功能/Kano、满意度 | 决策者和使用者分离、采购约束、组织环境 |
| 教育/学习研究 | 人群阶段、学习动因、学习方式、课程评价、价格接受、价值观 | 家长与学生视角分离、学习阶段、场景强度 |

## 变量选择规则

- 每个核心研究问题至少对应一个变量。
- 主体分析变量说明后续分析方式、适用图表和可支撑结论；甄别、配额、跳题与质检变量说明其执行作用。
- 需要用行为解释态度时，搭配相应行为变量；单一态度或认知研究按目标选题。
- 不要只选背景变量，背景变量主要用于交叉和解释。
- 非标项目先生成场景/任务树，再选择变量。
- 变量不能只服务好奇心，必须服务项目决策或报告结构。

## 题型映射规则

| 变量类型 | 优先题型 | 说明 |
|---|---|---|
| 唯一状态 | 单选 | 如当前主品牌、是否购买、使用阶段 |
| 多重行为 | 多选 | 如使用场景、渠道、痛点、功能需求 |
| 频率/程度 | 单选或矩阵单选 | 选项应固定，保留逻辑顺序 |
| 多对象评价 | 矩阵单选 | 品牌、功能、场景的同一量表评价 |
| 多对象用途归属 | 矩阵多选 | 品牌 × 用途、产品 × 场景 |
| 优先级 | 排序题或限选多选 | 样本负担高，谨慎使用 |
| 开放反馈 | 填空 | 必须预留编码或词频分析方案 |
| 功能优先级 | 按目标选限选／排序、重要性评价、Kano 或 MaxDiff | 简单优先次序用限选／排序；研究功能有无对满意反应的影响可用 Kano；大量项目相对取舍可用 MaxDiff，见 `specialized_question_modules.md` |

## 质量提醒

- 检查研究目标需要的态度与行为是否都有对应变量，不因题型单一自动扩题。
- 场景变量要具体到任务，不要只写“工作”“学习”“生活”。
- 品牌变量按目标选用“知道、用过、当前用、最常用、流失、迁移、忠诚、未来转向”，不默认全部测量。
- 功能变量如果用于 Kano，必须成对设计正反问题。
- 只有没有样本/执行作用，也没有分析或决策用途的变量，才是潜在孤儿变量。
