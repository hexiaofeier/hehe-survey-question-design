# 历史问卷考古总结 v0.1

## 数据范围

- 来源：34 个历史问卷 `.xlsx`
- 抽取：3188 条疑似题目 / 说明行
- 原始文件处理方式：只读，不移动、不改名、不写回

## 第一判断

这批文件不是普通题库，而是“用户调研问卷结构库”。最有价值的不是单题原文，而是反复出现的问卷组织方式：

`问卷说明 / 人群分类 / S或Q甄别 / A行为 / B动因痛点或评价 / C场景或产品功能 / D营销或价值观 / Z背景信息 / 结束语`

问卷设计 Skill 应沉淀：

1. 每类项目如何拆模块；
2. 每个模块常测哪些变量；
3. 变量通常用什么题型；
4. 题目如何通过跳题和引用形成用户路径；
5. 主体分析题能否进入后续分析与报告；甄别、路由、配额和质检题的执行作用是否明确。

## 结构规律

| 模块 | 常见角色 | 考古观察 | 对 Skill 的启发 |
|---|---|---|---|
| 问卷说明 | 项目说明、样本规则、访问提示 | 几乎每份问卷都有说明页 | 新项目必须先明确调研对象、样本条件、终止规则、配额边界 |
| 人群分类 | 将受访者分成用户、潜在用户、家长、学生、B端角色等 | 教育、学习和硬件类项目经常先分人群 | 需要分层比较或分流时先明确对应人群 |
| S/Q 甄别 | 有甄别作用或配额设计作用的年龄、城市、身份、经验、品类使用、品牌使用、排除项 | S/Q 是后续所有题目的 Base 根，但不是所有背景题都应放在 S | 先明确样本条件；前置招募已确认的条件可沿用，无需重复筛选；普通画像题后置 |
| A 行为链路 | 认知、了解、使用、购买、频率、渠道、价格 | A 模块承接“这个人有没有真实行为” | 变量库要把态度题和行为题分开 |
| B 动因/痛点/评价 | 购买动因、学习动因、选择因素、问题、满意度 | 很多项目在 B 模块完成核心洞察 | 按目标选择动因、阻碍或评价模块 |
| C/D 场景或功能 | 场景、功能、Kano、品牌迁移、任务类型 | 非标项目通常在这里展开 | 新赛道重点不是套题，而是先生成场景/任务树 |
| 价值观/态度 | X/E/H/I 等模块，常用于解释分群 | 教育、消费、健康类问卷常有价值观 | 价值观题应服务分群解释 |
| Z 背景信息 | 无甄别或配额作用的性别、年龄、城市、学历、年级、婚育、家人性别/年龄段、职业、行业、岗位、个人收入区间、家庭收入区间等 | Z 通常放最后 | Z 是背景补充和交叉变量库 |

## S/Z 模块归位规则

### S 部分

S 部分原则上只保留有甄别作用或配额设计作用的题目。典型用途包括：

- 判断是否进入目标样本；
- 判断是否终止问卷；
- 判断是否进入核心样本或对照样本；
- 形成必须控制的配额；
- 决定后续主体模块的 Base 或跳题路径。

如果某道题只是用于后续画像、交叉分析或背景补充，即使它是年龄、城市、身份、行业等常见人口学变量，也不应默认放在 S 部分。

例如问卷中的 `S3 当前身份或职业阶段`、`S4 行业或专业方向`，如果项目不按身份或行业设置进入条件、终止条件或配额，就更适合后置到 Z 部分；如果项目明确要求按学生/职场人、行业或岗位做配额，则可以保留在 S 部分。

### Z 部分

Z 部分一般用于背景补充和后续交叉分析。常见内容包括：

- 性别；
- 年龄；
- 城市；
- 学历；
- 年级；
- 婚育；
- 家人性别 / 年龄段；
- 职业；
- 行业；
- 岗位；
- 个人收入区间；
- 家庭收入区间。

这些题只有在承担甄别、终止、配额或关键分层作用时才前置到 S；否则应放在 Z，避免筛选题过长、过早暴露画像意图，并降低无关人群在开头的答题负担。

## 高频题型

| 题型 | 用途 | 设计提示 |
|---|---|---|
| 单选 | 核心状态、唯一主选项、阶段判断、未来意愿 | 常用于筛选、主品牌、主场景、态度等级 |
| 多选 | 使用品类、渠道、动因、痛点、功能需求 | 常与“至多N项”“选项随机”一起出现 |
| 矩阵单选 | 多品牌、多功能、多场景的同一量表评价 | 是满意度、功能表现、频率、Kano 的主力题型 |
| 矩阵多选 | 品牌 × 用途、产品 × 场景、功能 × 人群 | 适合建立差异化定位，但问卷负担较重 |
| 填空 | 第一提及品牌、开放原因、未来期待 | 需要谨慎使用，后续最好配编码方案 |
| 排序题 | 广告偏好、考虑因素、优先级 | 适合强制优先级判断 |

## 可复用设计模式

### 行为链路模式

常见结构：

`知道 / 了解 / 试用或购买 / 当前使用 / 最常用或核心 / 满意度 / 继续使用或推荐`

适用：AI 应用、教育产品、在线课程、智能硬件、SaaS、消费产品。

设计要求：

- 先判断是否需要完整行为链路；
- 不只问满意度，要先问使用阶段和具体场景；
- 区分“用过”“现在还在用”“最常用”“曾经用过但流失”。

### 动因-阻碍-痛点模式

常见结构：

`为什么开始 / 为什么购买 / 使用中遇到什么问题 / 为什么不买或不用 / 未来需要什么`

适用：新品验证、需求挖掘、用户增长、流失归因、产品机会判断。

设计要求：

- 同一变量最好同时有正向动因和反向阻碍；
- 对已有用户和潜在用户分开问；
- 痛点题后面要能接解决程度、功能需求或购买意愿。

### 品牌/产品迁移模式

常见结构：

`曾经最常用品牌 / 当前最常用品牌 / 流失品牌 / 迁移品牌 / 忠诚品牌 / 迁移原因 / 回归可能 / 付费后转向`

适用：AI 助手、家政平台、云办公产品、教育品牌、消费电子。

设计要求：

- 研究迁移时补充使用与变化题；仅研究认知时不展开本模式；
- 要设计过去-现在-未来的时间轴；
- 要用隐藏题或派生变量区分流失、迁移、忠诚。

### 场景/任务树模式

常见结构：

`核心场景 / 场景下使用品牌或工具 / 场景满意度 / 场景迁移原因 / 场景功能表现`

适用：AI 应用、学习硬件、教育服务、B 端办公软件。

设计要求：

- 面对新产品、新赛道时，优先生成场景/任务树；
- 每个场景模块可以复用：用途、品牌/产品、满意度、迁移/流失、表现评分；
- 场景题要能回到报告中的用户任务和业务机会。

### Kano/功能优先级模式

常见结构：

`如果能实现某功能，你如何评价 / 如果不能实现某功能，你如何评价`

适用：产品功能优先级、SaaS、教育智能硬件、平台服务能力。

设计要求：

- Kano 必须成对出现，不能只问喜欢某功能；
- 功能列表需要来自预研或场景拆解；
- 输出时要标明后续会进入 Kano 分析。

## 对 hehe-survey-question-design 的启发

- 先明确样本条件与必要的筛选路径，再设计主体题；已确认的招募条件可沿用；
- S 部分只放有甄别、终止、配额或 Base 分流作用的题；普通画像和交叉变量后置到 Z；
- 先判断受访者身份和使用阶段，再问态度；
- 先生成场景 / 任务树，再处理非标题目；
- 主体分析变量提前绑定分析方式和结论；样本与执行变量说明其作用；
- 历史题目可参考，但不要无脑复用原题。
