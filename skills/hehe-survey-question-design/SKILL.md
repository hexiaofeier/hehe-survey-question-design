# 用户调研问卷设计拆题器

## 技能定位

本技能负责用户调研工作流的问卷设计阶段：

`项目目标 / 资料消化 → 研究问题树 → 变量维度 → 问卷题目 → 字段字典 → 图表与结论映射`

它把研究目标拆成可测变量和可执行问卷。主体分析题要能接到后续数据分析和报告；甄别、路由、配额与质检题要说明在样本和执行中的作用。

本技能可独立完成问卷设计。回收后的数据清洗、质量检查、统计、图表与报告另按项目安排；环境中已有 `hehe-survey-analysis-workbook`、图表制作或报告写作能力时可选用，也可由其他工具或人员承接。

## 输入

优先收集以下材料：

- 项目 brief、研究背景、业务目标；
- 资料消化卡、预研摘要、竞品或产品资料；
- 调研对象、样本范围、配额或排除条件；
- 工具设计关键决策，如样本总量、样本结构、配额口径、关键题型或研究方法；
- 预计报告用途和目标读者；
- 已有问卷初稿或历史问卷参考；
- 目标问卷平台及其导入方式；未指定时默认采用问卷星文本导入格式；
- 用户明确指定必须保留、必须排除或必须重点分析的问题。

材料不全时，先用已知目标和对象形成可审阅的暂定问卷，把影响样本筛选、配额、选项或分析的缺口标在相应位置。研究目标或受访者对象完全不明时，先询问这两项，再设计问卷。

## 必读 references

执行前读取：

1. `references/archaeology_summary.md`：历史问卷结构和设计模式；
2. `references/variable_library.md`：变量库和研究目的映射；
3. `references/quality_check_rules.md`：问卷质检规则；

5. `references/design_workpaper_schema.md`：研究边界、变量、题目用途和质检的设计底稿字段。

## 工作流程

### 1. 明确项目边界

先判断本次调研属于哪类任务：

- 新品需求验证；
- 满意度研究；
- 产品体验研究；
- 竞品比较；
- 付费转化研究；
- 用户画像 / 分群；
- AI 应用研究；
- B 端 / SaaS / 企业数字化；
- 教育、学习、家长或学生人群研究；
- 其他自定义场景。

必须说明：

- 本次调研要支持什么决策；
- 调研对象是谁，不是谁；
- 最终报告最需要回答的 3-5 个问题；
- 后续是否需要交叉分析、Kano、满意度、品牌迁移或付费转化。

### 2. 设计样本和受访者分层

先明确回答对象和必要的 S/Q 甄别逻辑，再进入主体问卷；已有名单或前置招募已确认的条件可直接沿用。

承担甄别、配额控制、样本分组或后续分流作用的题，应放在相应控制发生之前；仅用于事后画像和交叉分析的背景题通常后置。前置招募已核实的信息可直接沿用。

至少明确：

- 样本进入条件；
- 终止条件；
- 关键配额或人群分层；
- 本研究需要区分的身份，如已有用户、潜在用户、流失用户、决策者或使用者；
- 后续主体模块的 Base。

没有额外甄别或分流需要时，可直接从主体问题开始，不为凑模块重复筛选。

同时记录工具设计关键决策，只记录会影响样本、问卷模块、题型设计或后续分析的方法口径，包括：

- 样本总量、有效样本量、主样本 / 对照样本比例、关键分组最低样本量；
- 招募来源、按个人／家庭／企业计样的口径，以及同一对象多人回答或重复评价的关联规则；
- 目标人群、纳入 / 排除条件、用户状态、年龄 / 职业 / 地区等核心分层；
- 城市、年龄、性别、年级、用户类型、品牌 / 产品使用等配额口径；按 `design_workpaper_schema.md` 明确独立配额或交叉单元、数量、计入条件及满额处理；
- 是否引入 Kano、NPS、价格测试、联合分析、MaxDiff、因子分析、聚类等方法。

若缺失的决策会改变甄别、配额或关键题型，向用户集中询问；可以先设计的模块继续推进。样本量和高级统计方法仅在本项目需要时确定，不为空项补问。

选用 Kano、NPS、价格测试、MaxDiff 或联合分析时，读取 [专项题组设计](references/specialized_question_modules.md) 对应部分，确定题目、呈现方式和所需字段。

### 3. 拆研究目标和研究问题树

把泛目标拆成可回答问题。例：

`了解用户需求` 不可直接进入问卷，应拆成：

- 用户在哪些场景下产生需求；
- 当前替代方案是什么；
- 现有方案痛点是什么；
- 哪些人群需求更强；
- 哪些功能或服务可能驱动转化。

输出研究问题树，并标明每个子问题属于事实、行为、态度、动因、阻碍、评价、意愿还是背景交叉。

把 brief、报告大纲和用户明确要求中的必答问题逐项列出；涉及不同场景、品牌或人群时分别列明，标注对应题目和预计可分析的 Base。缩短或分卷后仍须逐项检查能否回答；若不能，补题或调整分卷与样本，确需放弃的研究问题交用户确认，不用总体题代替场景题。

### 4. 形成研究假设和变量

每个核心研究问题至少映射一个变量。变量必须说明：

- 变量名称；
- 变量定义；
- 测量原因；
- 适合题型；
- 样本/执行作用，或后续分析方式与可支撑结论。

优先从 `variable_library.md` 中选择变量；遇到新赛道时，先生成场景 / 任务树，再补充非标变量。

需要从资料提炼场景、变量或选项时，读取 [题目设计方法](references/question_design_methods.md) 第一节，将 brief、已有访谈、产品资料和必要的定向搜索加工成候选题目；依据记在设计底稿，材料未覆盖处可提出自拟题或开放探索题。

### 5. 变量映射题目

把变量转成题目时必须保留：

- 题号；
- 模块；
- 题型；
- 题干；
- 选项随机性：有选项的题显式标注“选项固定”“选项随机”“行项目随机/列选项固定”等；纯填空题底稿记“不适用”，详稿不加此标签；
- 选项；
- 是否限选；
- 跳题逻辑；
- Base；
- 字段名。

完整题干、选项与建卷配置以同版详稿为准；设计底稿按题号关联变量、字段、Base和分析用途，不重复抄写整道题。最终导入文档只使用平台可识别的题目格式。

需要用行为解释态度时配相应行为题；品牌研究按目标选择认知、使用、主用、流失或迁移等环节。仅研究认知或特定行为时，保留能回答目标的题组即可。

编写或调整题目时，按 [题目设计方法](references/question_design_methods.md) 第二节落实测量对象、回忆时间、单位、受访者知情程度和回答尺度；跨场景、品牌或人群比较的题目保持可比口径。

产品、概念或竞品测试另按该方法第四节确定比较分组、品牌与价格展示时点、体验及提问顺序。

### 6. 确定每道题的用途

每道题标明其作用：样本甄别/配额、跳题/Base、质检，或主体分析。主体分析题说明：

- 适合出图时的建议图表类型；
- 是否需要交叉分析；
- 可支撑的报告结论；
- 是否进入数据分析大表；
- 是否进入图表库；
- 是否存在解释风险。

甄别、路由、配额和质检题可以不单独出图。只有既不影响问卷执行与样本界定，也不支持分析或决策的题目，才标记为“孤儿题候选”并建议删除或请用户判断。

对需要比较或解释的结论，按 [题目设计方法](references/question_design_methods.md) 第三节核对所需答案、交叉变量与分流后可用人数，落实到现有用途表；样本规划按项目需要展开。

### 7. 生成问卷交付物

从以下常见结构中选用本项目需要的模块，保留已确认研究问题的覆盖：

1. 问卷说明；
2. 人群分类；
3. S/Q 甄别题；
4. A 行为链路；
5. B 动因、痛点或评价；
6. C/D 场景、功能、品牌迁移或 Kano；
7. 价值观或态度题，若确有分群解释价值；
8. Z 背景信息；
9. 结束语。

模块名称可以根据项目调整。交付文档保留题号、题型、选项和必要跳题；每题 Base 保留在设计底稿。

默认交付三份：供确认修改的 Markdown（`.md`）建卷详稿及同内容 Word（`.docx`）阅读详稿，以及供平台文本导入的 Markdown（`.md`）纯问卷。两份详稿内容一致，开头用简短“问卷说明”交代设计目的、结构、主要逻辑与配额状态，再按内容分区逐题写完整题干、必要的方括号标签和完整原选项。Markdown逐行列选项；Word用表格呈现选项，标签和说明用更小的灰色文字。标签写题型、选项固定/随机及限选、显示、跳转、互斥、引用等实际配置。无 `[选答]` 即必答，无显示条件即所有合格受访者回答；不逐题重复默认规则。纯导入稿按问卷星可识别的文本格式保存，不混入内部设计说明、分区和配置；题干与每个选项分别成行，题间空一行，选项不带字母或数字前缀，选项内的半角空格须处理为不会拆项的写法并保持原意。三份文件的题号、题干、选项和顺序一致。具体格式按 `output_schema.md`；用户指定其他平台时适配相应导入格式。

内部设计说明与受访者作答说明分开；调查介绍、作答对象、概念或方案描述等影响回答的信息须在实际问卷相应位置展示。文本导入不支持的说明及设置写入两份详稿对应位置，供建卷人员使用。研究假设、变量表、分析映射和质检另留设计底稿，用户需要时再交付。默认任务止于问卷文件交付及静态核对；平台导入、在线配置、预览、发布和回收仅在用户另行要求时处理。

### 8. 执行质检

使用 `quality_check_rules.md` 逐项检查，输出：

- 必须修改；
- 建议修改；
- 可保留但需备注；
- 待用户确认。

不得把只有好奇价值、既不服务样本与执行也不支持分析的题目伪装成必要题。

文件交付前走查题目与逻辑。用户另行要求预试时，按 `quality_check_rules.md` 的“预试与修订”，让目标受访者按完整路径答题，核对甄别终止、配额、跳题、选项理解、缺失值、字段编码和实际用时；根据实际发现修订问卷与字段字典并复测。未做预试的版本注明状态，不影响问卷文件交付完成。

## 交付与设计底稿

详稿承接平台设置，不另附重复配置清单，格式见 `references/output_schema.md`。研究边界、变量与题目映射、字段字典和质检按 `references/design_workpaper_schema.md` 留在设计底稿；用户要求设计依据或完整设计包时再提供。

用户只要求修改部分题目或质检现有问卷时，交付修改后的题目和必要的逻辑配置变更，不强制重做整套设计包。

已有三稿且交付可用修订版时，同步三稿与受影响字段，列明改动题号；用户只需审阅意见或修改片段时，按其要求交付。

## 质量标准

- 问卷目标、变量、题目、样本/执行作用或分析用途形成闭环；
- 每个主体题都有明确 Base；
- 每个变量能说明为什么要测；
- 主体分析题能说明后续怎么分析；筛选、路由和质检题能说明执行作用；
- 单选类别边界清楚；多选保留合理共存项、明确排他项；选项覆盖和顺序合理；
- 需要行为解释的态度结论有对应行为题；
- 场景题具体到任务，不停留在大类；
- 品牌题覆盖本次目标需要的认知、使用、主用、迁移或忠诚环节；
- Kano 题成对设计；
- 问卷长度和矩阵题负担可控；
- Markdown 与 Word 详稿的标题、说明、分区、逐题文字及选项内容一致，允许段落和表格布局不同；与纯导入稿的题号、题干、选项和顺序一致。每题的显示、跳转、选项显示与呈现规则可执行，配额已确认与待确认状态清楚；
- 会改变目标人群、配额或关键研究方法的未定口径明确标出，交由用户决定。

## 交付说明

交付时向用户说明：

- 本版问卷服务的研究目标；
- 使用了哪些历史考古规律和变量库模块；
- 问卷总题量、核心模块和主要跳题；
- 哪些题强关联后续图表库和报告脚本；
- 哪些题属于非标设计，需要重点审；
- 哪些假设、选项或配额仍待确认。
